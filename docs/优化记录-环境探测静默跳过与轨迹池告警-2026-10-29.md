## 1. 背景与目标

10-26 文档定位了根因：RDP 断开即锁屏时，输入桌面从 `Default` 切到 `Winlogon`，真实鼠标滑块必失败，且每 3 分钟一轮的刷新循环持续空打 Token 接口、产生风控日志与通知轰炸。10-27 分析补充：轨迹池可用数一度 < 6，池空风险无人感知。

原第 2 步方案（完整版）设计了 Redis 双进程退避状态机 + 失败分类 + 样本冷却，评审后与老板确认**按精简版实施**：保留最重要的两件事，砍掉一切非必需机制。

## 2. 范围决策（保留 2 件，砍掉 6 件）

| 决策 | 内容 | 理由 |
|---|---|---|
| ✅ 保留 | 环境探测 + 刷新入口全局静默跳过 | 核心痛点：锁屏期间 Token 接口 0 调用、0 风控日志、≤1 条通知/3h |
| ✅ 保留 | 轨迹池告急告警（可用数 < 6，6h 冷却） | 池空会导致所有账号静默卡死，是唯一无其他兜底的感知手段 |
| ❌ 砍掉 | `env_backoff.py` Redis 状态机（5 个配置 key） | 环境是全局的，进程内拦截即可；scheduler 触发滑块走 HTTP 到 websocket 进程，探测在那里兜底 |
| ❌ 砍掉 | 真拒型（reject）退避 | 现有 3 次重试 + 180s 周期 + 加权排队已是天然降频 |
| ❌ 砍掉 | 样本冷却 `_sample_state.json` | `_take_drag` 已保证同次求解不重样；跨任务复用风险未坐实 |
| ❌ 砍掉 | scheduler 候选排除改造 | 见"已知边界" |
| ❌ 砍掉 | `ENV_UNAVAILABLE` 哨兵 + 编排层第三返回值透传 | 入口拦截已挡掉绝大部分；漏网（滑块中途锁屏）按普通失败处理可接受 |
| ❌ 砍掉 | 成败记账 / 配置开关体系 | 探测不可用即跳过、恢复即自动回归，无需记账；回滚 = 删入口 20 行 |

## 3. 实现内容（1 新文件 + 4 处小改，共 +83 行）

| 文件 | 改动 |
|---|---|
| `common/services/captcha/desktop_env.py`（新增） | ctypes 探测：`OpenInputDesktop` + `GetUserObjectInformation(UOI_NAME)` 读输入桌面名；`Default` 以外（`Winlogon`/`Screen-saver`）判为锁屏；**任何探测失败一律放行**（非 Windows / API 失败不拦截），单次 <1ms |
| `websocket/app/services/xianyu/cookie_token_manager.py` | ① `_refresh_token_with_lock` 入口拦截：不可用则置 `skipped_env_not_interactive`、发一条 `env_not_interactive` 通知、直接 return——Token 接口 0 调用、不触发滑块、不产生风控日志。② `_notify_trail_pool_low_if_needed`：读 `real_mouse_slider.get_trail_pool_state()`，可用数 < 6 时经 `send_account_notification` 告警，进程内 6h 全局冷却 |
| `websocket/app/services/xianyu/token_manager.py` | cookie 刷新循环识别 `skipped_env_not_interactive`：静默推进到下一周期，不再触发 5 秒重试风暴 |
| `websocket/app/services/xianyu/notification_manager.py` | 标题映射 +`env_not_interactive`；`_is_token_related_error` 关键词 +"Token刷新暂停"/"环境不可交互"，使该通知走 3 小时冷却 |
| `common/services/captcha/real_mouse_slider.py` | `_load_drags` 后记录池水位到 `_last_pool_state`（`available=None` 哨兵表示未加载过，浏览器模式不误告警） |

关键设计：拦截点放在 `refresh_token` 入口而非某个循环里——cookie 循环（3 分钟）、token 循环（20 小时）、消息触发的刷新三条路径一次全覆盖。

## 4. 锁屏期间的行为链路

```
cookie 循环每 180s → _refresh_token_with_lock 入口
  → env_block_reason() 返回 locked:Winlogon
  → 置 skipped_env_not_interactive + 发 1 条通知（3h 冷却，第 2 条起自动跳过）
  → token_manager 识别该状态 → 正常推进周期（无 5s 重试）
解锁后下一轮 → 探测恢复 Default → 一切照旧
```

## 6. 已知边界

- **scheduler 侧**：Token 续期任务每轮仍会对临期账号调一次 Token 接口（其触发的滑块走 websocket 内部接口，会被快速拦住失败）。如需"锁屏期间全系统零接口调用"，可在 `token_renewal_task` 加同款探测（约 8 行），本期未做。
- **前台被抢占 ≠ 锁屏**：探测通过后到滑块执行之间若恰好被 UAC/其他窗口抢前台，按普通滑块失败处理（不记环境跳过、不发锁屏通知），属预期行为。
