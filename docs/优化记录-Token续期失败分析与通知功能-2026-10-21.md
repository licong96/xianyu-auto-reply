## 1. 事故回顾：2026-10-20 Token 续期大量失败

### 现象

管理后台「Token续期日志」页面出现 **155 条失败记录**（2026-10-20 17:32:11 ~ 18:32:45），
成功率 0%，失败原因统一为「滑块处理失败：过滑块失败」，全部集中在账号 `2795001015`。

### 完整链路（根因）

1. 17:32 起，闲鱼 Token 接口对该账号返回 `FAIL_SYS_USER_VALIDATE`
   （`RGV587_ERROR::SM::哎哟喂,被挤爆啦,请稍后重试`）——账号被风控，必须过滑块才能取新 Token。
2. scheduler 的 Token 续期任务触发滑块处理，委托 WebSocket 服务 `/internal/captcha/solve`。
3. WebSocket 侧使用**真实鼠标滑块引擎**（系统设置 `captcha.slider_mode=real_mouse`），
   需要把滑块浏览器窗口激活到 Windows 前台才能回放真人鼠标轨迹。当次日志反复出现：

   ```
   无法激活 Windows 前台窗口，已取消物理鼠标回放: hwnd=1050040, foreground=0
   ```

   当日共出现 **180 次**（典型原因：会话锁屏 / 远程桌面断开或最小化 / 前台被抢占）。
4. 配置为「真实鼠标失败不回退」，且 `captcha.block_remote_calls=true` 封锁远程滑块通道，
   形成死循环：Token 接口要滑块 → 滑块过不了 → 续期失败，持续约 1 小时。
5. **19:12:01 风控自然解除**，Token 接口恢复正常，新 Token 写入缓存
   （有效期至 2026-10-21 06:52），WebSocket 自动重连，系统自愈。

### 教训

- scheduler 侧 Token 续期任务失败时**只写库不发通知**；
- websocket 侧「滑块验证失败」分支**没有接通知**（只写风控日志）；
- 会通知的 `captcha_max_retries_exceeded` 分支因重试计数每次刷新归零而永远触发不到；
- 结果：两边默默失败、默默记日志，一小时无人知晓。

## 2. 已落地的修改

### 2.1 Token 续期任务间隔调大（2026-10-20 晚）

- 修改：`xy_scheduled_tasks` 表中 `task_code='token_renewal'` 的 `interval_seconds`
  **20 秒 → 120 秒**
- 通过 scheduler 内部接口 `POST /internal/tasks/reload` 热加载生效，无需重启
- 目的：降低请求频率，减少「被挤爆」类风控触发概率
- 注意：scheduler 只在循环启动时加载一次配置，直接改库后必须调用 reload 接口或重启服务

### 2.2 失败通知功能上线（2026-10-21）

| 位置 | 改动 |
|---|---|
| 新增 `common/services/account_notification_dispatch.py` | 通用账号通知模块：查询账号绑定的启用渠道 → 复用 `notification_utils` 渠道发送函数 → 按（账号+通知类型）进程内冷却。支持 feishu/lark、dingtalk、bark、email、webhook、wechat、telegram、pushplus |
| `scheduler/app/services/scheduler/token_renewal_task.py` | 每轮执行完对失败账号调用 `send_account_notification`，标题「❌ Token续期失败」，**每账号每小时最多 1 条**；通知异常捕获，不影响主任务 |
| `websocket/app/services/xianyu/cookie_token_manager.py` | 滑块验证失败分支补发通知（类型 `captcha_failed`），**附带验证链接**便于人工手动处理；消息含「Token刷新失败」关键词，走 websocket 侧 **3 小时冷却** |
| `websocket/app/services/xianyu/notification_manager.py` | 标题映射表新增 `captcha_failed → ❌ 滑块验证失败` |

验证情况：

- 4 个文件编译通过；新模块用真实飞书渠道联调发送成功；冷却逻辑验证正确
  （冷却期内二次发送被拦截）
- scheduler、websocket 均通过 `POST /internal/system/self-restart` 热重启完成加载，
  重启后配置（120 秒间隔）从数据库重新读取，未丢失

### 2.3 通知链路说明（现状）

- 通知渠道：`飞书通知`（feishu webhook + 签名校验），`xy_notification_channels` 启用 ✅
- 账号绑定：`2795001015`、`2056611706` 均已绑定渠道并启用 ✅
- scheduler 侧冷却：1 小时（`account_notification_dispatch.DEFAULT_NOTIFY_COOLDOWN_SECONDS = 3600`）
- websocket 侧冷却：Token 相关错误 3 小时（`NotificationManager.token_refresh_notification_cooldown = 10800`），普通通知 5 分钟
- 注意「正常令牌过期/令牌为空」类错误（`_is_normal_token_expiry`）不会发通知，属设计行为

## 3. 已知遗留问题与建议

1. **真实鼠标滑块依赖可交互桌面**：窗口无法置前（锁屏/RDP 断开/前台被抢占）时
   real_mouse 引擎必失败。建议保持 Windows 会话常亮、禁用锁屏与睡眠；
   已另行检查自动登录 + 锁屏配置（见下）。
2. **real_mouse 失败不回退**：如需可再加「环境类失败（无法置前）自动降级 CDP stealth
   引擎」的补丁，已评估未实施（CDP 过检率较低，乱回退反而增加风控）。
3. **远程滑块兜底未启用**：`captcha.block_remote_calls=true` 保持封锁，
   老板明确不需要远程通道。若未来有多台可交互 Windows 节点，可再放开。
4. **风控计数器归零问题**：`captcha_max_retries_exceeded` 通知因每轮刷新重试计数
   归零而难以触发，目前由新增的 `captcha_failed` 通知覆盖实际场景。
