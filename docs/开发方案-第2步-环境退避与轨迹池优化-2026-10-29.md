> 状态：已按**精简版**实施（2026-10-29 上线，见 `docs/优化记录-环境探测静默跳过与轨迹池告警-2026-10-29.md`）。
> 本文档描述的完整版（Redis 退避状态机 / 真拒退避 / 样本冷却 / scheduler 排除）经评审后**未实施**，仅作设计存档；实际落地范围以优化记录为准。
> 范围：方案 B（10-26 文档 7.3 节）+ 10-27 分析的两条优化建议合并实施
> 原则：**不改数据库结构（无 DDL）**；现有正常路径行为不变；全部改动可通过配置开关回滚；
> 生效方式：websocket / scheduler 热重启（`POST /internal/system/self-restart`），不停机

## 1. 目标与效果指标

| 目标 | 效果指标 |
|---|---|
| 环境不可交互（锁屏/RDP 断开）时安静等待 | 环境不可用期间 Token 接口调用 = 0、风控日志新增 = 0、每账号通知 ≤1 条/3h |
| 环境恢复自动回归 | 恢复后下一轮立即正常（退避状态自动归零） |
| 真拒型失败（轨迹被拒）降频 | 同账号连续被拒时重试间隔拉大，轨迹样本消耗降 ≥50% |
| 轨迹池告急可感知 | 可用数 < 6 时 6 小时内收到 1 条通知 |

## 3. 新增模块设计

### 3.1 `common/services/captcha/desktop_env.py`（新文件，约 80 行）

```python
ENV_DESKTOP_OK = "Default"          # 可交互桌面的名称
def get_input_desktop_name() -> str | None
    # ctypes: OpenInputDesktop(0, False, GENERIC_READ)
    #   → GetUserObjectInformation(UOI_NAME=2, StringBuilder)
    # 返回 "Default"/"Winlogon"/"Screen-saver"；打不开返回 None
def env_block_reason() -> str | None
    # 非 Windows → "not_windows"（返回 None=不拦截，保持容器兼容）
    # 输入桌面 != "Default" → "locked:Winlogon"
    # 二次校验：当前会话存在 logonui 进程 → "locked:logonui"
    # 均通过 → None（可用）
```

- 纯函数、无 IO 副作用，两个服务进程都可调用；
- 探测结果**不做缓存**（每次调用实时探测，成本 <1ms）。

### 3.2 `common/services/captcha/env_backoff.py`（新文件，约 150 行）

每账号两类失败独立退避，Redis 存储（key 带 TTL，双进程共享）：

```
key: env_backoff:{account_id}     TTL 24h
value: {"env": {"tier": 0..3, "until": epoch, "consec": n},
        "reject": {"tier": 0..2, "until": epoch, "consec": n}}

API:
  block_reason(account_id, kind) -> str | None   # 在退避期内返回原因
  record_failure(account_id, kind)               # 档位 +1，until = now + tier[ tier ]
  record_success(account_id, kind)               # 清零
  env_unavailable() -> str | None                # 代理 desktop_env.env_block_reason()
```

- 档位配置（xy_system_settings 新增 key，读取失败用内置默认）：

| key | 默认 | 含义 |
|---|---|---|
| `captcha.env_check_enabled` | `true` | 总开关，`false` = 全部回到现状 |
| `captcha.env_backoff_tiers` | `180,600,1800,3600` | 环境型退避档位（秒） |
| `captcha.reject_backoff_tiers` | `600,1800,3600` | 真拒型退避档位（秒） |
| `captcha.trail_cooldown_seconds` | `7200` | 同账号样本复用冷却 |
| `captcha.trail_pool_min` | `6` | 可用池告警阈值 |

- Redis 读写在 `common/db/redis_client.py` 既有封装上实现；读取配置走现有 system settings 缓存模式（改库热生效）。

### 3.3 `common/services/captcha/real_mouse_slider.py` 改造

**(a) 环境失败分类**（不改正常返回路径）：

```python
class EnvNotInteractiveError(RuntimeError): ...   # 新异常

# _ensure_window_foreground: 激活失败时 raise EnvNotInteractiveError(detail)

```

**(b) 轨迹样本冷却 + 池告警**：

- 旁路状态文件：`human_trails/_sample_state.json`
  `{"samples": {"human_trail_pass_xxx.json": {"last_used": {account_id: epoch}, "last_reject": epoch}}}`
- `_load_drags` 加载后按状态文件过滤：该账号 `now - last_used[acct] < trail_cooldown_seconds` 的样本本次不进入候选；
- `solve()` 每次选用样本后写 `last_used`；`_slide_code == 300` 判定时写 `last_reject = now`；
- 池告警：过滤后可用数 < `trail_pool_min` 时调用通知（见 4.4），进程内冷却 6 小时防刷屏；
- 写状态文件失败仅记日志，不影响滑块主流程（文件锁用临时文件 rename 方式，避免并发损坏）。

## 4. 接入点改造（按进程）

### 4.1 websocket `app/services/xianyu/token_manager.py`（cookie_refresh_loop）

每轮刷新**之前**：

```python
if settings_on and (reason := env_backoff.env_unavailable()):
    env_backoff.record_failure(cookie_id, "env")
    logger.info(f"【{cookie_id}】环境不可交互（{reason}），跳过本轮 Token 刷新")
    self.last_cookie_refresh_time = time.time()  # 正常推进，避免 5 秒重试风暴
    continue
if reason := env_backoff.block_reason(cookie_id, "env"):
    logger.info(f"【{cookie_id}】环境退避期内（{reason}），跳过")
    self.last_cookie_refresh_time = time.time()
    continue
```

- 关键效果：环境不可用时**完全不碰 Token 接口**（不产生风控、不消耗轨迹）。

### 4.2 websocket `app/services/xianyu/cookie_token_manager.py`

- 滑块失败分支识别第三返回值 `env_unavailable`：
  - 风控日志 `error_message` 记「环境不可用：{detail}」（与"过滑块失败"区分，后台可统计）；
  - `env_backoff.record_failure(account_id, "env")`；
  - 通知类型 `env_not_interactive`（复用 NotificationManager 3 小时冷却）；
  - 通知文案附处理指引（运行桌面 tscon 脚本 / 查 session-state.log）；
- 真拒型失败（现有"过滑块失败"分支）：`record_failure(account_id, "reject")`；
- 任意路径刷新成功：`record_success(account_id, kind)`。

### 4.3 scheduler `app/services/scheduler/token_renewal_task.py`

`_load_candidates` 排除条件追加：

```python
# 追加：处于环境/真拒退避期的账号本轮跳过（Redis 共享状态，由 websocket 侧写入）
for candidate in ...:
    if env_backoff.block_reason(candidate.account_id, "env") or \
       env_backoff.block_reason(candidate.account_id, "reject"):
        continue
```

- scheduler 不再对已知的不可用账号每 120 秒空转；
- 保持现有 `processing` 风控日志排除逻辑不变（互补关系）。

### 4.4 通知模块 `websocket/app/services/xianyu/notification_manager.py`

标题映射表新增：

```python
"env_not_interactive": "⚠️ 环境不可交互（锁屏/远程断开）",
"trail_pool_low":      "⚠️ 真人轨迹池告急",
"reject_backoff":      "⚠️ 滑块连续被拒（退避中）",   # 真拒型连续 ≥3 次时发送
```

`account_notification_dispatch` 通用模块无需改动（按 notification_type 冷却）。

## 5. 完整失败处理流程（改造后）

```
取 Token 遇风控 → 需要滑块
   │
   ├─ env 探测不可用 ──→ 记 env 退避 + 风控日志"环境不可用" + 通知(3h冷却)
   │                      scheduler 下轮跳过该账号
   ├─ 环境可用，滑 3 次全被拒 ──→ 记 reject 退避 + 现有通知
   │                            （退避期内刷新循环/scheduler 双双静默）
   ├─ 池可用数 < 6 ──→ trail_pool_low 通知（6h 冷却）
   └─ 任一成功 ──→ 退避清零，一切照旧
```

## 9. 边界与风险

| 风险 | 缓解 |
|---|---|
| OpenInputDesktop 在服务所在之外的会话运行（未来迁容器） | 非 Windows/打不开时**不拦截**（返回不可用但由开关控制；二次校验 logonui 兜底） |
| 退避期间账号 Token 真到期 | Token TTL 6~15h，环境档最长 60min、reject 档最长 60min，余量充足；且失败通知保留 |
| 状态文件并发写 | 临时文件 + rename；写失败降级为"无冷却状态" |
| Redis 不可用时退避失效 | Redis 不可用时降级为"无退避"（现状行为），与系统现有降级风格一致 |
