# 运营知识库：自动续售与发货机制

> 整理时间：2026-10-16；2026-10-19 增补自动续售规则说明。来源：真实故障排查记录。

## 一、自动续售是怎么工作的

```
一键上架时：建素材 → 发布商品 → 建卡券并绑定 → 建续售规则（rule，记住 current_item_id）
买家下单 → 发货（卡券内容发给买家）→ 调度服务每 5 秒扫描
→ 发现"已履约订单" → 创建续售事件（延迟 60 秒）
→ 用素材重新发布一个新商品 → 卡券绑到新商品 → 规则指向新 item_id
→ 下一轮成交继续循环，商品永不断货
```

关键机制：

- 规则（`xy_auto_relist_rules`）靠 **商品 ID（item_id）** 关联，与商品上下架状态无关。
- 在闲鱼 APP 里手动下架/再上架**不会**破坏续售关联，放心操作。
- 续售是"成交后才触发"，商品没卖出去不会重复发布。
- 每个订单只会触发一次续售（按订单号 + 发布幂等号去重）。

### 触发条件清单（对照排查用）

一笔订单要触发自动续售，必须同时满足以下条件（来源：`auto_relist_discovery.py` / `auto_relist_task.py` / `auto_relist_utils.py`）：

**规则侧**（发现阶段，缺一不可）

- [ ] 续售规则存在且 `enabled = true`，状态不是 `error` / `paused`（`xy_auto_relist_rules`）
- [ ] 没有该规则 + 当前商品下处于活跃状态的事件（防并发重复触发）
- [ ] 订单的 `item_id` == 规则的 `current_item_id`（订单挂在"当前代商品"上）

**订单侧**（已真实履约，满足其一）

- [ ] 订单状态为 `shipped` 或 `completed`，且发货方式为 `auto`（即时自动发货）或 `scheduled`（定时补发货），且发货内容（卡券内容）非空
- [ ] 或 `card_only_delivered = true`（纯卡券已送达）且订单未取消 / 退款 / 退款中

**执行前置校验**（不满足会跳过或暂停事件）

- [ ] 素材还在素材库中且归属一致（否则暂停："素材已移出素材库或归属不一致"）
- [ ] 闲鱼账号正常且有 Cookie（否则暂停："闲鱼账号已停用或缺少 Cookie"）
- [ ] 卡券存在、已启用，且关联着当前商品（否则暂停："自动发货卡券已停用或不存在" / "自动发货卡券未关联当前商品"）
- [ ] 订单当前仍未退款 / 取消（变了则跳过："订单状态已变化，不再触发自动续售"）

**会让续售永久停摆的操作**

- 在商品管理里**删除**商品（删平台商品 + 清卡券关联，见第三节第 5 条）
- 关闭续售规则 / 停用卡券 / 移出素材库 / 停用闲鱼账号

## 二、发货方式：auto（自动） vs scheduled（定时补发货）

| | auto 自动发货 | scheduled 定时补发货 |
|---|---|---|
| 触发时机 | 买家付款瞬间，消息服务实时发货 | 调度任务周期扫描"未成功发货"的订单，稍后补发 |
| 定位 | 主力路径，买家秒收卡券 | 兜底路径，自动发货失败时补上 |
| 对买家的区别 | 无，最终都收到卡券内容 | 无，只是晚几分钟 |

**建议：两个开关都打开**（账号设置里的「自动发货」+「定时补发货」）。这是"主力 + 兜底"的组合，不是二选一。

注意：从资料池一键上架本身不属于任何一种发货方式——它只负责把商品挂到闲鱼（发布商品 + 绑卡券 + 建续售规则）。发货方式是在买家下单之后才产生的。

## 三、2026-10-16 故障与修复记录

### 1. 定时补发货的订单不触发自动续售（重要）

**现象**：订单 5127354723045028218 已成交、卡券已送达，但商品没有自动重新上架。

**根因**：续售的订单发现逻辑写死只认 `delivery_method = 'auto'`。该订单的卡券是由"定时补发货"任务补发的，记录为 `scheduled`，于是被永久过滤，事件表为空。处理侧校验其实已认 `scheduled`，发现侧漏了，属于代码不对称。

**修复**：`common/services/auto_relist_discovery.py` + `common/services/auto_relist_utils.py` 两处统一放宽为 `auto / scheduled` 均为有效履约（commit 87d4bce）。

**排查套路**（以后再遇到不续售）：
1. 看 `xy_auto_relist_rules`：enabled、status、current_item_id 是否等于订单的 item_id。
2. 看订单的 status / delivery_method / delivery_content 是否满足发现条件。
3. 看 `xy_auto_relist_events` 有没有事件、状态是什么。
4. 看调度日志（scheduler/logs/scheduler.log）里「自动续售」轮次是否正常。

### 2. 卡券内容变成 `<coroutine object ...>`

**根因**：一键上架构建卡券正文时调异步方法 `_build_card_text()` 漏写 `await`，协程对象被存进卡券（commit bc0dd66）。

### 3. 夸克网盘出现"假提取码"

**根因**：夸克分享查重（share-list）时把 `pwd_id`（即链接后缀）误当提取码入库，卡券里出现 `提取码：396954e6b996` 这种和链接重复的冗余行。夸克链接本身自包含，不需要提取码。已修复（commit bc0dd66）。

### 4. 网盘侧职责调整

网盘管理的「上架」简化为「入池」：**只负责创建分享链接 + 导入资料池**。售价、封面、描述等上架信息统一在资料池编辑/一键上架时填写。职责划分：

- 网盘管理：浏览 → 分享 / 入池
- 资料池：审核 → 编辑（售价、封面等）→ 一键上架

### 5. 商品管理里"删除"商品会彻底废掉该商品的自动续售（2026-10-19 确认）

**背景疑问**：商品管理列表里删除商品后，续售规则的绑定是否失效？

**结论**：实际效果上不会再自动续售，但原因不是"规则绑定失效"。

**代码事实**（`items.py` 删除接口 → `item_delete_service` → `item_service.delete_item`）：

- 删除 = 调闲鱼平台删除 API（`mtop.alibaba.idle.seller.pc.item.delete`）删平台商品 + 删本地 `xy_catalog_items` 记录 + 删卡券关联（`card_item_relations`）。
- **续售规则表 `xy_auto_relist_rules` 不会被清理**，`current_item_id` 仍指向已删商品。
- 续售执行前有一道前置校验：卡券必须关联当前商品（`AutoRelistRule` → `CardItemRelation.item_id == old_item_id`）。删除商品时卡券关联被清掉，即使扫描到历史订单，事件也会判为 paused，原因"自动发货卡券未关联当前商品"。
- 链条：平台商品没了（不会再成交）+ 卡券关联被清（续售前置校验过不了）→ 两条路都堵死。

**与"下架"的区别**：下架（off-shelf）不动卡券关联和规则，再上架后续售照常；删除是清道夫行为，会废掉续售能力。不想续售了可以删除，想暂时停售请用下架或关闭续售规则。删除后建议顺手清理对应的续售规则，避免留下永远 paused 的僵尸规则。

### 6. 弹窗内操作"没反应"可能是提示被遮挡

Toast 提示层级（z-100）曾被弹窗遮罩（z-200）挡住，校验报错看不见。已提升到 z-999（commit bc0dd66）。以后遇到"点击没反应"，先怀疑校验提示被遮挡或浏览器需要硬刷新（Cmd+Shift+R）。
