## 1. 已落地功能

### 1.1 卡券联动（第 1 步）

- `common/services/card_share_text.py`（新增）：卡券正文渲染抽到 common 层，
  `MaterialPoolService._build_card_text` 改为委托调用（行为不变）。
- 手动「重新分享」（`POST /material-pool/{id}/reshare`）成功后**自动重建绑定卡券的
  `text_content`**：仅当卡券正文仍引用旧地址时才重建，人工编辑过的卡券不覆盖。
- 重建逻辑下沉到 `backend-web/app/services/share_renew_service.py`，手动与自动续期共用。

### 1.2 到期自动续期（第 2 步）

- 续期阈值：**到期前 7 天**（`DEFAULT_RENEW_BEFORE_DAYS`，新地址有效期 30 天，旧地址过期前仍可访问）。
- backend-web 新增内部接口 `POST /internal/material-pool/reshare-expiring`
  （`X-Internal-Token` 鉴权，`app/api/routes/internal_share.py`）：扫描
  `share_expire_at <= NOW()+7天` 且资料池 `status='listed'`、已绑卡券的链接，
  逐池复用现有 PanClient 重建分享 → 写回 `pan_url/pan_code/share_id/share_expire_at/last_renew_at`
  → 重建卡券正文 → 置 `check_priority=1`（新地址优先巡检）。
- scheduler 新增定时任务 `share_renew`（默认 12 小时，可在定时任务配置页调整），
  通过 HTTP 触发上述内部接口。
- 每条链接的处理结果 + 每轮汇总落 `xy_share_check_logs`（task_type=renew）。

### 1.3 内容存活巡检（第 3 步，只记录 + 通知，不做自动处理）

- 新增独立包 `share_health_check/`（DrissionPage 只装在 paper_crawler venv，
  沿用"独立 venv + 子进程"既定模式）：
  - `browser.py`：巡检专用 Chromium（独立端口 9145 + 独立用户数据目录，不影响爬虫/滑块实例）
  - `checker.py`：单页判定状态机，总预算 **15 秒**——错误容器优先（百度 `#error-new #shareError`、
    夸克失效文案白名单）→ 有效容器（夸克 `tbody.ant-table-tbody` 行数、百度 `div.file-name` +
    "共 N 个文件"）→ 预算耗尽按风控特征判 `risk`、否则 `error`（**error 永不等于失效**）
  - `runner.py`：取批（`check_priority=1` 插队，最久未查优先，只扫在售商品）→ 逐条检查、
    条目间**随机等待 2~3 秒** → 回写 `last_check_status/last_check_at` + 落日志。
    **夸克/百度链接自动拼接提取码**：表里有 `pan_code` 且地址未带 `pwd=` 时追加
    `?pwd=码`（已有 query 用 `&`），已有 `pwd=` 或不支持的网盘不改动；
    实际打开的完整地址记入日志与通知，人工点开即可直达。
- scheduler 新增定时任务 `share_health_check`（默认每天一次）：子进程执行巡检包，
  解析 `RESULT_JSON:` 摘要；**invalid / empty / risk** 按资料池绑定的闲鱼账号发通知
  （复用 `account_notification_dispatch`，6 小时冷却），人工到资料池点「重新分享」修复。
- 命中风控特征时本批次**提前结束**，避免加重风控。

### 1.5 卡券正文地址带提取码（买家点开即达）

- 拼接逻辑下沉到 `common/utils/share_url.py: build_check_url()`，
  卡券正文渲染（`card_share_text.render_card_text`）与存活巡检共用一份：
  夸克/百度地址有提取码且未带 `pwd=` 时自动拼接（`?pwd=码` / `&pwd=码`），
  已有 `pwd=` 不重复拼；卡券里"提取码"行保留，兼顾手动输入场景。
- 存量卡券不受影响的说明：卡券正文在发货时实时读取，但**已生成的卡券内容
  要下次续期/重新分享重建后才会带 pwd**；如需立即生效可对资料批量点重新分享。

### 1.4 日志管理页

- 新表 `xy_share_check_logs`（模型 `common/models/share_check_log.py`，
  DDL 镜像 + `COLUMN_MIGRATIONS` 存量迁移已加到 `init_database.py`）。
- `xy_material_pool_pan_links` 新增 4 字段（`last_check_status/last_check_at/last_renew_at/check_priority`），
  存量库启动时自动迁移。
- 日志接口 `GET/DELETE /admin/share-check-logs`，前端页面
  `frontend/src/pages/shareCheckLogs/`（菜单：日志管理 → 分享续期巡检日志），
  支持按类型（续期/巡检）、结果、网盘筛选；续期记录显示新旧地址对比。

### 1.6 定时任务页可见 + 续期日志地址带提取码（收尾修复）

- **任务种子**：`init_database.py` 的 `DEFAULT_SCHEDULED_TASKS` 追加两行
  （`share_renew` 网盘分享到期续期 43200s、`share_health_check` 网盘分享存活巡检 86400s），
  走既有 `init_scheduled_tasks()` 的 INSERT IGNORE 种子逻辑。
  之前页面看不到任务是因为任务列表只读 `xy_scheduled_tasks` 表，新任务代码只注册了
  运行时兜底配置没写种子行；**重启 backend-web 或 scheduler 跑一次初始化后即可在
  定时任务管理页看到并配置**。
- **续期日志带 pwd**：`share_renew_service._log_renew` 落库的新旧地址统一过
  `build_check_url()` 拼接提取码（失败路径的旧地址用旧提取码 `old_code`，避免张冠李戴），
  与卡券正文、巡检日志同一口径。旧日志行无法回补（日志表无提取码列，属已知限制）。
  同步更新 `test_share_renew_service.py` 断言（新地址 `?pwd=2222`、旧地址 `?pwd=1111`）。
- **手动触发白名单**：scheduler 内部接口 `internal.py` 的 `trigger_task` 任务代码白名单
  补上 `share_renew` / `share_health_check`（调度分发本身已支持，仅白名单漏注册）。
