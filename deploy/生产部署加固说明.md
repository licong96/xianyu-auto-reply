# 生产服务器部署加固说明

> 配套文件：`.env.production`（强随机密码）+ `docker-compose.prod.yml`（安全覆盖层）
> 适用对象：把本项目部署到公网服务器的场景。

## 一、启动命令

```bash
cd /opt/xianyu-auto-reply   # 项目所在目录

docker compose -f docker-compose.yml -f docker-compose.prod.yml \
  --env-file .env.production up -d --build
```

`docker-compose.prod.yml` 是覆盖层，与原版 `docker-compose.yml` 叠加使用，**不修改原文件**，以后合并作者更新不会冲突。

## 二、覆盖层做了什么

| 加固项 | 说明 |
|---|---|
| 官方基础镜像 | MySQL/Redis 从 `registry.cn-shanghai.aliyuncs.com/zhinian-software/*` 换回 Docker 官方 `mysql:8.0` / `redis:7-alpine`，去掉对作者自建镜像的信任 |
| 端口只绑本机 | 4 个端口（8089/8090/8091/9000）全部绑定 `127.0.0.1`，公网零暴露；对外只走宿主机 Nginx 的 443 |
| 关闭远程内容 | 强制 `ENABLE_REMOTE_ADS/ANNOUNCEMENTS/POPUP=false`，dashboard 不再请求作者服务器 `xy.zhinianboke.com` |
| 收紧 CORS | 覆盖原配置中的 `*`，只允许你的管理域名 |
| 强随机密码 | MySQL root、MySQL 业务账号、Redis、INTERNAL_API_TOKEN 均为 `openssl rand -hex` 生成的随机值 |
| 卡密对接留空 | `CARD_DOCK_BASE_URL` 留空，「一键创建卡密密钥」等走作者服务器的功能不可用、零流量 |

## 三、宿主机 Nginx（唯一公网入口）

```nginx
server {
    listen 443 ssl http2;
    server_name xy-admin.your-domain.com;   # 改成你的域名

    ssl_certificate     /etc/letsencrypt/live/xy-admin.your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/xy-admin.your-domain.com/privkey.pem;

    client_max_body_size 50m;

    location / {
        proxy_pass http://127.0.0.1:9000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 86400s;   # WebSocket 长连接需要
    }
}
```

证书：`certbot --nginx -d xy-admin.your-domain.com`

## 四、防火墙

### 入站（只放行 SSH / HTTP / HTTPS）

```bash
ufw default deny incoming
ufw allow 22/tcp
ufw allow 80/tcp
ufw allow 443/tcp
ufw enable
```

### 出站（推荐，限制容器被入侵后的外传）

项目正常运行只需访问：闲鱼/淘宝/支付宝/阿里云系域名 + 你自配的 AI API 域名。可用 iptables 按 UID/网络限制，简单方案是安全组层面只放行必要目标，或安装 `ufw` 后对出站做白名单。至少做到：**MySQL(3306)/Redis(6379) 绝不对外**（compose 里已只在内网暴露，双保险）。

## 五、首次登录必改

1. 后台默认账号 `admin / admin123` → 登录后立刻改强密码（个人设置）。
2. 检查 `.env.production` 未被提交 git（已确认 `.gitignore` 排除 `.env*`；本文件名为 `.env.production`，建议再核对一次 `git status`）。
3. 把 `.env.production` 里的 `CORS_ORIGINS`、`FRONTEND_PUBLIC_URL`、Nginx `server_name` 三处改成你的真实域名。

## 六、部署后自检清单

```bash
# 1. 容器状态
docker compose -f docker-compose.yml -f docker-compose.prod.yml --env-file .env.production ps

# 2. 公网只能访问 443（从外部机器执行，应全部超时/拒绝）
nc -zv 你的服务器IP 8089 && echo "危险:8089暴露" || echo "OK"
nc -zv 你的服务器IP 8090 && echo "危险:8090暴露" || echo "OK"
nc -zv 你的服务器IP 9000 && echo "危险:9000暴露" || echo "OK"

# 3. 确认没有到作者服务器的流量（应无输出）
docker exec xianyu-backend-web sh -c 'cat /proc/net/tcp >/dev/null' # 容器内无 ss 时用宿主机:
sudo tcpdump -i any host xy.zhinianboke.com -c 20   # 跑 10 分钟应零流量

# 4. 服务健康
curl -s http://127.0.0.1:9000/health
curl -s http://127.0.0.1:8089/health
```

## 七、更新流程（保持加固层）

```bash
git fetch upstream && git checkout main && git merge upstream/main
git checkout custom && git merge main
# 合并后重新构建（覆盖层文件不受影响）
docker compose -f docker-compose.yml -f docker-compose.prod.yml \
  --env-file .env.production up -d --build
```

> 提醒：不要用 README 里的 `curl ... xy-update.zhinianboke.com/deploy.sh | bash`，那是直接执行作者服务器上的脚本，等于把服务器控制权交出去。用上面的本地 compose 流程。
