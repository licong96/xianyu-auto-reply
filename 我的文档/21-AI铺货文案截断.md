# AI 铺货文案截断

- 提交：`cc983a5`

## 问题

AI 铺货报「文案生成失败：AI返回内容不是合法JSON」。提示词里本来就要求只返回 JSON，失败原因不是少写一句「请返回 JSON」。

当时一次生成 5 条长中文描述，配置的输出上限是 2048 token。模型已经按 JSON 开始写，写到中途被截断。解析用整段 `json.loads`，外层没闭合就整批失败，已经写完的条目也丢掉了。错误信息只截取前 200 字，看起来像模型在第二条标题处停住，其实后面还有内容，只是日志没记全文。

## 改法

- 按本批条数提高输出上限：每条按 600 token 估算，5 条至少 3000。配置里填得更高时仍用配置值，自动提高最多到 8192
- 调用时优先带 `response_format: json_object`。接口返回 400 时，退回原来的几种请求形态
- 全文不是合法 JSON 时，抽出已经闭合、并且带标题和描述的对象继续用；缺的条数再请求一次补上。截断且完全无法解析时，改成减半重试，最多再补两轮
- 日志记下返回字数和 `finish_reason`。`length` 或 `max_tokens` 表示又被上限截断
- 提示词补了一条：字符串里不要出现英文双引号和换行，保证单条对象能闭合
- 网页端和手机端的默认生成条数从 5 改为 3

涉及：

- `backend-web/app/services/ai_listing_text_generator.py`
- `common/services/ai_text_client.py`
- `frontend/src/pages/product-publish/ai-listing/AiListingTaskPanel.tsx`
- `xianyu-mobile/app/(tabs)/mine/ai-listing.tsx`

刷新页面后，新建任务的条数输入框默认是 3。后端需要用到包含这次提交的进程；本次修改后本机 8089 已按新代码重启过。
