# 资料池一键上架对齐素材库（发布选项方案）

- 状态：**已实施（2026-10-16）**，后端冒烟测试 11 项全部通过、发布请求全字段构造验证通过、前端类型检查与生产构建通过
- 依赖：[09-资料池页面与上架编排](./09-资料池页面与上架编排.md)、[12-一键上架选择类目](./12-一键上架选择类目.md)、[22-网盘浏览与直选上架方案](./22-网盘浏览与直选上架方案.md)

## 背景与问题

资料池一键上架编排（`list_to_pan`）建素材/发布时把素材库的大部分字段硬编码成默认值：

- 图片只有 1 张封面（素材库最多 9 张）、无视频、无原价
- 运费硬编码包邮（`shipping_method="free"`）、不支持自提、无宝贝所在地
- 成色固定"全新"、无品牌
- 数量固定 1、无规格/SKU

发布接口 `PublishSingleRequest` 本身全部支持这些字段，素材库新增/编辑（`MaterialFormModal` + `ProductPublishForm`）与单品发布本来共用一套表单组件——缺的只是资料池没接入这套封装。

## 方案

不新造字段体系：资料池行新增一个 JSON 列 `publish_options` 存"发布选项覆盖项"，一键上架弹窗内嵌素材库同款表单（`ProductPublishForm` + 图片/视频上传），提交时把完整选项传给后端，编排层 merge 后同时用于「建素材」和「发布请求」，并持久化到行上（失败重试复用，与类目持久化同一哲学）。

**merge 优先级**：行内已持久化选项 < 本次调用传入选项（单个弹窗回显持久化值后整包传回，幂等；批量弹窗传公共选项，逐行与各行已存选项叠加）。

标题/描述/售价如在选项中给出，以选项为准并回写行上（`row.title/description/price`），保证资料池记录与已发布商品一致；未给出时沿用现有自动生成规则。

## 数据流（单个一键上架）

```
资料池行点「一键上架」
  → 弹窗预填：标题/描述/价格（行值或自动生成）、图片（已存选项或封面）、
    类目（行内已持久化）、其余选项（行 publish_options）
  → 用户可改：多图/视频/原价/运费/自提/所在地/数量/成色/品牌/规格，或调整标题描述价格
  → POST /material-pool/{id}/list { account_id, category, publish_options }
  → 后端 merge（行内 < 本次）→ 持久化 → 建素材（merge 后字段）→ 发布（merge 后字段）
  → 失败原地停留，重试时选项已持久化无需重填
```

## 兼容性

- `publish_options` 为空的老记录：行为与改动前完全一致（默认值路径不变）
- 批量上架：公共选项逐行 merge，行内已有个别选项的不会被覆盖
- 普通卖家账号：表单按账号能力收起鱼小铺字段（规格/库存/视频），提交时自动清空视频与规格（与单品发布行为一致）
