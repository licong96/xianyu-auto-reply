# 网盘浏览与直选上架方案

- 状态：**已实施（2026-10-12）**，后端 4 接口已用真实网盘 curl 验证（浏览/分享查重/导入幂等/池状态标记），前端类型检查通过
- 依赖：[08-夸克网盘桥](./08-夸克网盘桥.md)、[09-资料池页面与上架编排](./09-资料池页面与上架编排.md)、[12-一键上架选择类目](./12-一键上架选择类目.md)

## 背景与目标

资料池现有流程是「爬虫采集 → 下载到本地 → 上传网盘 → 分享 → 补信息 → 一键上架」，方向是「本地文件 → 网盘」。

本方案新增一条反向通路：网盘里**已经有**的文件，人工在网页上浏览、判断，补充好信息后**直选一键上架**。不涉及本地上传、下载（明确不做）。

目标拆成三步：

1. 前端新增侧边栏页面，网页方式浏览夸克网盘目录（文件夹/文件列表）；
2. 网页上对某个文件点按钮创建分享链接（查重，不重复创建）；
3. 选中文件 → 弹窗补信息（标题/售价/描述/类目/封面）→ 一键进入现有资料池上架流程。

## 关键设计决策

### 1. 复用 `xy_material_pool` 表，不建新表

两种来源的数据在后半段（补信息、审核、上架、续售）字段需求完全一致，只有「`pan_url` 怎么来的」不同。逐字段核对结论：

- `paper_name`（NOT NULL）← 网盘文件名；
- `source_url`（NOT NULL + 全表唯一）← 合成键 `quark://<网盘完整路径>`（路径含文件名），同时满足非空、唯一、来源可识别、防重四个诉求；
- `source_type` ← 新增值区分来源（爬虫侧为 `zxxk`，网盘侧见「待确认」第 4 条）；
- `local_path` / `file_hash` ← 留空（nullable）；
- `pan_type` / `pan_path` / `pan_url` / `pan_code` / `share_id` / `share_expire_at` ← 建记录时直接写入；
- `status` 初始值 ← `pending`（待审核），之后走与爬虫数据完全相同的状态机；
- 上架编排 `list_to_pan`、卡券、续售规则、现有全部接口：**零改动**。

防重语义：对网盘同一文件重复点「上架」，捕获 `uq_material_pool_source_url` 唯一键冲突，直接返回已存在的记录，不插重行。

已知取舍：去重键是路径，网盘里重命名文件后再上架会被当成新记录。影响小，第一版接受。

### 2. 网盘直选的行永远不会误触发上传

`upload_pool_row_to_pan` 第一关就是「已有 `pan_url` 拒绝重复上传」，网盘直行建记录时 `pan_url` 已就绪，爬虫侧的上传入口对它天然免疫。两侧入口（爬虫上传 vs 网盘直建）在代码层分开。

### 3. 性能结论（本机实测）

`kuake list` / `share` / `user` 单次约 0.6–2 秒（子进程 + 一次网络请求）。浏览、分享、状态检查全部走同步 HTTP + 前端 loading 即可；后端用 `asyncio.to_thread` 包一层避免阻塞事件循环。不引入后台任务队列。

### 4. 分享幂等

后端创建分享前先 `share_list()` 按文件路径反查已有分享（借鉴现有 `_lookup_share_id` 反查模式），已有则直接返回旧链接；没有再创建。`KUAKE_SHARE_DAYS` 沿用现有配置。

## 后端设计

新增 `backend-web/app/api/routes/pan_browser.py`，路由前缀 `/api/v1/pan`，照 `material_pool.py` 的模式（`ApiResponse` 包装、`get_current_active_user`、`get_db_session` 依赖注入）。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/pan/status` | 网盘连接状态，转调 `QuarkPanClient.user_info()`，页面加载时调用；失败时前端明确提示「网盘凭证失效，请更新 kuake_cli/.env」 |
| GET | `/pan/entries?path=<路径>` | 列出指定目录内容（fid、file_name、path、size、dir、mtime），转调 `list_dir()`，默认 path=`/`；同时按 `source_url=quark://路径` 批量比对资料池，给每个条目附 `pool_status`（无记录为 null） |
| POST | `/pan/share` | body: `{path}`；先按路径反查已有分享，无则创建；返回 `{share_url, pan_code, share_id, share_expire_at}` |
| POST | `/pan/import` | 核心接口，见下 |

### `POST /pan/import`

职责：把网盘里的一个文件导入资料池（建记录 + 确保有分享链接）。

请求体：

```json
{
  "pan_path": "/资料池/学军中学/2026/数学期中.pdf",
  "file_name": "数学期中.pdf",
  "file_size": 12345678,
  "create_share": true
}
```

处理逻辑：

1. `source_url = "quark://" + pan_path`；按 source_url 查已有记录：
   - 命中 → 直接返回该记录（幂等，不重复创建分享、不插重行）；
2. `create_share=true` 且无现成分享 → 调 `share()` 创建，失败则整体报错（记录不落库，避免半截状态）；
3. INSERT `xy_material_pool`：`paper_name=file_name`、`source_type=<网盘来源值>`、`pan_type="quark"`、`pan_path/pan_url/pan_code/share_id/share_expire_at` 就绪、`file_size` 写入、`status="pending"`、`local_path=None`；
4. 捕获唯一键冲突（并发下兜底）→ 改为返回已存在记录；
5. 返回新建的池记录（复用 `_row_to_dict` 的形状），前端随后用现有 `PUT /material-pool/{id}` 补充标题/售价/描述/封面/类目。

**注册路由**：`backend-web/app/api/routes/_exports.py` 加 import 与 `include_router`（照现有 CUSTOM 模式）。

**不改的部分**：`material_pool_service.py`、`quark_pan_client.py`、`common/models/material_pool.py`（表结构零改动）。

## 前端设计

技术栈沿用现有模式：React 18 + Tailwind + framer-motion + 自封装组件（Select / ConfirmModal / Loading），无 antd。

### 新增文件

**`frontend/src/api/panBrowser.ts`**

4 个接口封装 + 类型定义（`PanEntry`、`PanShareResult`、`PanImportResult`），风格对齐 `materialPool.ts`。

**`frontend/src/pages/pan-browser/PanBrowser.tsx`**

**层级显示方案（与 kuake 接口形态对齐）**：`list` 接口一次只返回一层、无递归能力，且目录深度不确定，因此采用**面包屑 + 单层表格逐层下钻**（访达/夸克网盘网页版模式），页面永远只显示当前一层，深度只体现在面包屑长度上，层级再多 UI 结构不变。备选方案（左树右表、表格内嵌懒加载展开行）因需自绘树组件、与「目录少文件多」的网盘形态不匹配而放弃。

- 顶部：连接状态指示（进入页面调 `/pan/status`）+ 当前路径面包屑（点击回跳任意层级，首页为根目录）；
- 主体：目录内容表格——表格第一行为 `..` 返回上级（根目录时不显示），文件夹排前（点击进入下一层），文件行显示大小/修改时间；每行操作列：
  - 「分享」按钮：调 `/pan/share`，弹窗显示链接 + 一键复制；
  - 「上架」按钮：打开上架弹窗（见下）；
- 「资料池状态」列（辅助人工判断）：`GET /pan/entries` 返回时后端把当前层文件路径与 `xy_material_pool.source_url`（`quark://路径`）批量比对，已导入的行显示状态徽章（待审核/在售/不售），人扫一眼即可分辨哪些处理过、哪些是新文件；
- 路径状态写进 URL（`/pan-browser?path=...`，`encodeURIComponent` 编码——网盘目录名含全角冒号等特殊字符，如 `来自：分享`）：刷新不丢位置、可收藏直达、支持浏览器前进后退；
- 每层切换有 loading 状态（每次下钻约 0.7 s）。
- 上架弹窗（复用现有积木）：
  - 标题、售价、描述：普通表单项；
  - 类目：`PlatformCategoryRecommender`（与资料池一键上架弹窗同一组件）；
  - 封面图：`uploadMaterialPoolCover`（复用商品发布图片上传接口，必填）；
  - 提交：先 `POST /pan/import`，再 `PUT /material-pool/{id}` 补信息；成功后提示「已导入资料池，请前往资料池审核上架」；
- 视觉与交互照 `MaterialPool.tsx`。

## 数据流（一次完整操作）

```
用户在网盘页对某文件点「上架」
  → 弹窗补信息（标题/售价/描述/类目/封面，必填校验）
  → POST /pan/import {pan_path, file_name, file_size}
      → 已有记录？返回旧记录
      → 无分享？创建分享
      → INSERT xy_material_pool（status=pending）
  → PUT /material-pool/{id}（标题/售价/描述/封面，复用现有接口）
  → 记录出现在「资料池」页面，状态=待审核
  → 人工审核通过 → 一键上架（现有 list_to_pan，零改动）
```

## 已确认决策（2026-10-12 与老板确认）

1. **浏览范围**：从 `/资料池` 起步，可向上浏览到网盘根 `/`，不做额外权限限制；
2. **菜单名称**：「网盘管理」，侧边栏放在「资料池」旁边；
3. **第一阶段范围**：文件夹仅支持「浏览 + 分享」，文件夹级上架放第二阶段；
4. **`source_type` 取值**：`quark-manual`（夸克网盘人工直选，爬虫侧为 `zxxk`）；
5. **导入后状态**：`pending`（待审核），与爬虫数据一致，人工审核通过后再一键上架；
6. **重复导入**：命中已存在记录时直接返回旧记录，前端提示「该文件已在资料池」。

**实现期修正**：类目选择不在网盘导入弹窗中——现有资料池流程本就支持在上架弹窗里选类目（见 [12-一键上架选择类目](./12-一键上架选择类目.md)），网盘导入弹窗只收集标题/售价/描述/封面，类目沿用上架时选择，交互更一致。

**实现期补充**：分享查重以 `share-list` 返回的 `first_fid`（首个文件 fid）与目录条目 `fid` 比对为准（实测字段可靠），比按路径/文件名比对准确。

**实施后的两轮优化（2026-10-12 当晚）**：

1. **爬虫行关联**：`/pan/entries`、`/pan/share`、`/pan/import` 除了按 `source_url=quark://路径` 匹配，再按 `pan_path` 匹配——爬虫行（source_url 是学科网链接）在网盘页也能显示池状态，网盘直选导入命中爬虫行时直接返回（不重复建记录）；若命中行尚无分享链接，建分享后补齐网盘字段并置 `pending`（实测：网盘页 5 个爬虫文件全部正确显示 在售/待审核，导入返回原爬虫行）。
2. **资料池来源筛选**：列表接口与页面新增 `source_type` 筛选（全部/学科网爬虫/网盘直选），表格试卷名列带来源徽章（网盘直选=紫色、学科网=灰色）。
