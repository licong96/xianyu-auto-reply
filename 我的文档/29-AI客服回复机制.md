# AI 客服自动回复机制

- 状态：**已实施**（2026-11-05，本机 py_compile + tsc 通过；待线上验证效果）
- 涉及提交：`1da389d`、`9f0a998`、`f5514a7`、`7465160`、`93a690a`

## 本文档解决什么

闲鱼买家发来消息时，由大模型自动生成客服回复。本文档记录这套功能的**整体架构、提示词分层体系、配置维护入口和关键机制**，作为后续维护、调优、排障的依据。上游原版 README 只有一句话介绍，无设计文档。

业务范围：全部为**虚拟资料（电子版）**，百度网盘 + 夸克网盘双盘发货，无物流无邮费。**不支持议价**（一口价政策）。

## 消息处理主链路

```
买家消息（闲鱼 WebSocket，websocket 服务）
   │
   ▼
auto_reply_service.handle_chat_message      ← 路由与兜底，不做"智能"
   自己发的消息 → 触发人工介入暂停
   系统消息 / 自动发货触发 → 跳过回复
   商品归属校验 → 去重 → 过滤词
   │
   ▼
get_reply 优先级：关键词规则 ──► AI 回复 ──► 默认回复 ──► 静默
   │
   ▼
ai_reply_engine.generate_reply              ← 智能发生的地方
   组装分层提示词 → 调大模型 → 双方消息入库
   │
   ▼
xy_ai_chat_messages（对话上下文）  xy_auto_reply_logs（决策日志）
```

## 提示词分层体系（核心设计）

发给模型的是 `[system, user]` 两条消息，system 按以下顺序拼装：

| 层 | 内容 | 来源 | 维护入口 |
| --- | --- | --- | --- |
| 统一话术 | 身份（虚拟资料店铺客服）+ 三种情境策略（砍价/问内容/日常）+ 示例 | 引擎内置 `default_prompts["unified"]` | 账号 AI设置 → 高级设置「统一话术覆盖」（unified key） |
| T1 全局规则 | 6 条红线：一口价、不编造、不承诺做不到的操作、不引导站外、诚实承认自动客服身份、复杂问题转人工 | 引擎内置，强制追加 | 改代码 |
| T2 店铺说明 | 虚拟商品/双网盘/无物流/补发售后等业务事实 | `ai_reply_settings.shop_prompt`，**带默认值** | 账号 AI设置 → 店铺说明（主配置入口） |
| T1+ 自定义规则 | 账号级 `_global` key，追加在系统规则之后 | `ai_reply_settings.custom_prompts` JSON | 高级设置「全店通用规则」 |
| L3a 商品档案 | 标题(120字)/价格/描述(2000字)，自动注入 | 商品库 `xy_catalog_items`，依赖商品同步 | 零维护 |
| L3c 商品补充 | 卖点/FAQ/格式/网盘说明等增量知识 | `xy_catalog_items.ai_prompt` | 商品管理 → AI提示词（单条/批量） |
| L4 对话历史 | 最近 10 条，注明 assistant 为客服本人回复 | 自动从 `xy_ai_chat_messages` 取 | 零维护 |
| L5 输出约束 | 只输出最终回复、≤80 字、temperature 0.3 | 引擎内置 | 改代码 |

要点：**规则和知识在进模型前分层拼装好，模型只负责"说话"；红线在系统层强制注入，任何自定义内容都压不住它。**

## 配置维护手册（日常视角）

| 想干什么 | 去哪干 | 频率 |
| --- | --- | --- |
| 全店口径（发货/退换/风格） | 账号管理 → AI设置 → **店铺说明** | 一次配置，数月一改 |
| 临时规则（活动/特殊情况） | 高级设置 → 全店通用规则 | 随时 |
| 整体替换话术风格 | 高级设置 → 统一话术覆盖 | 偶尔 |
| 上新商品 | 商品管理 → AI提示词，按「卖点/常见问题/注意事项」填，可批量 | 每次上新 |
| 排查"为什么没回复" | 自动回复日志页（`xy_auto_reply_logs` 的 decision_reason） | 按需 |

模型与连接参数（服务商/API地址/Key/模型名、启用时间段、人工暂停开关）同在账号 AI设置弹窗。

## 关键机制

| 机制 | 说明 |
| --- | --- |
| 一口价政策 | 全局规则第 1 条 + 店铺说明兜底；AI 口头报价与改价动作无联动（程序不改价），故禁止任何承诺 |
| 人工介入暂停 | 卖家手动回复后，自动暂停该会话（或按买家+商品维度）AI 回复，默认 10 分钟，可配 |
| 6 秒新消息去重 + 会话锁 | 买家连发消息只回最新一条；同一会话串行处理防并发 |
| 消息入库 | 双方消息写 `xy_ai_chat_messages`（上下文来源）；人工暂停期间/AI 未启用时的消息不入库，上下文会缺段 |
| 模型调用 | OpenAI 兼容（4 种降级重试）/ DashScope 应用 / Gemini / Anthropic；超时 30s；空回复/截断有重试 |
| AI 失败降级 | 生成失败或返回空 → 落默认回复 → 都没有则静默（日志可查原因） |
| 已下单用户开关 | `ai_reply_block_ordered_users`：有订单的买家跳过 AI |

## 历史演进（为什么这么改）

| 原设计 | 现状 | 原因 |
| --- | --- | --- |
| 议价功能（砍价话术、递减优惠、议价轮数限制、最大折扣配置） | **全部移除** | AI 只口头报价、程序不改价，链路断裂；口头承诺无法兑现有纠纷风险 → 改一口价 |
| 关键词意图分类（price/tech/default 本地匹配） | **移除**，情境判断交给模型 | 预 LLM 时代的遗留设计；"刀""还能"等子串误命中；全局规则兜底后误判无害 |
| 一套提示词 JSON 手填 | 分框可视化编辑 + 系统默认可查看 | JSON 手填易错；留空即用默认 |
| "绝不透露是 AI" | 诚实承认自动客服身份 | 参考成熟实践：冒充真人被戳穿伤信任且有平台风险 |
| 商品描述截断 800 字 / 回复上限 40 字 / temperature 0.5-0.7 | 2000 字 / 80 字 / 0.3 | 资料类商品描述长；40 字说不清；客服要稳定口径不要创意 |

## 已知边界与注意事项

1. **商品信息依赖商品库同步**：商品不在 `xy_catalog_items` 时，AI 只能拿到"商品信息获取失败"，答非所问——先查商品同步。
2. **议价相关设置字段**在后端 schema/引擎默认值中仍保留（兼容旧数据），前端已移除，均为死配置。
3. **意图统计归零**：`xy_ai_chat_messages.intent` 不再写入，后台议价统计恒为 0（历史数据保留）。
4. **移动端自定义提示词输入框是原始文本**（非 JSON），引擎解析失败静默忽略——该字段在移动端实际无效，待修。
5. **prompt 约束是概率性的**：极弱模型仍可能失守红线，换模型或加强 `_global` 措辞。
6. 修改引擎内置文案（统一话术/全局规则/默认店铺说明）需**同步三处**：`ai_reply_engine.py`、`ai_reply_service.py` 的 DEFAULT_AI_SETTINGS、`Accounts.tsx` 的 SYSTEM_DEFAULT_PROMPTS，注释中已互相标注。

## 调优闭环

上线后每周从 `xy_ai_chat_messages` 抽 AI 回复挑毛病，归类后补到对应层：
答错商品事实 → 补商品 AI提示词；说了不该说的 → 补全局规则/`_global`；某类问题话术差 → 改统一话术；啰嗦/格式乱 → 调输出约束。改完重启 websocket 验证。
