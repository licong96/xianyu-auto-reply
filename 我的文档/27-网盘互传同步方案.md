- 依赖：[23-多网盘并列查询与合并列表方案](./23-多网盘并列查询与合并列表方案.md)、[26-百度网盘接入部署与测试](./26-百度网盘接入部署与测试.md)
- 涉及提交：`7cf0f8c`（功能）、`a2292c0`（脚本与文档）

## 本文档解决什么

网盘管理页里，一个文件/文件夹只存在于百度或夸克其中一个盘时，点「同步到X」按钮，
自动把它搬到对端盘的**相同路径**，让一份文件同时出现在两个网盘、目录结构完全一致。
后续一键上架/发货可直接出两个盘的链接，不再需要人工「百度下载到本地 → 再上传夸克」。

## 使用方式

1. 网盘管理页（`/pan-browser`），条目只在其中一个盘时，操作列出现「同步到夸克」或「同步到百度」；
2. 点击后按钮变「同步中 x/y」，后台逐文件搬运（并发 2），完成/失败自动 toast 并刷新列表；
3. 两边都有的条目不显示按钮（「所在网盘」列显示两个盘即已同步）；
4. 前端显示条件：条目所在盘缺对端 + 对端盘在 `/pan/status` 中连接正常（`SYNC_PAIRS` 前端后端各有一份，改方向表要两边同步改）。

## 行为规则（已定稿决策）

| 场景 | 行为 |
| --- | --- |
| 目标盘已有同名文件、大小一致（0.5% 相对容差） | 跳过，不重复上传 |
| 目标盘已有同名文件、大小不一致 | 视为旧版本，**先删目标再传**（直接覆盖） |
| 文件夹 | 递归同步整棵目录树，路径原样照搬（目标路径 = 源路径，无前缀映射） |
| 单文件 | 只搬该文件 |
| 空文件夹 | 在目标盘创建同名目录 |
| 单文件失败 | 记错误继续，其余文件不受影响；任务最终状态仍可为 done（failed > 0） |
| 同一路径重复点击 | 拒绝：「该路径正在同步中」（内存 `_running_keys` 防重入） |
| 服务重启 | 任务进度丢失（内存态），重新点一次即可，已传部分自动查重跳过 |
| 同步后分享 | 第一版不自动创建分享；用现有分享按钮/入池流程逐盘出链接 |

## 接口契约（供 AI / 前端查阅）

### POST `/api/v1/pan/sync` 启动同步

请求：
```json
{"pan_type": "baidu", "path": "/闲鱼/资料池/多盘测试", "is_dir": true}
```
- `pan_type`：源盘，仅 `baidu` / `quark`；目标盘取对端（`SYNC_PAIRS = {"baidu": "quark", "quark": "baidu"}`）
- `path`：源盘绝对路径；越出 `PAN_ROOT_DIR`（默认 `/闲鱼`）时收拢到根目录
- 前置校验：对端盘已在 `PAN_ENABLED_PANS` 启用；磁盘水位通过

成功响应 data（任务快照，status=queued）：
```json
{
  "task_id": "4877bf02df48", "src_type": "baidu", "dst_type": "quark",
  "remote": "/闲鱼/资料池/多盘测试", "is_dir": true,
  "status": "queued", "total": 0, "processed": 0,
  "uploaded": 0, "skipped": 0, "failed": 0,
  "errors": [], "current": "", "created_at": 1760990000.0, "finished_at": null
}
```
失败：`success=false`，message 为可读原因（不支持的源盘 / 对端未启用 / 正在同步中 / 磁盘空间不足）。

### GET `/api/v1/pan/sync-status/{task_id}` 查询进度

- `status` 流转：`queued → running → done | failed`
- 进度字段：`total`（文件总数，running 后才有值）、`processed` / `uploaded` / `skipped` / `failed`、`current`（当前文件名）
- `errors` 最多保留 10 条，格式 `"<相对路径>: <错误摘要>"`
- 任务不存在：`success=false, message="任务不存在或已被清理"`（内存最多保留 100 条已完成记录）
- 注意：**done ≠ 全部成功**，需同时看 `failed` 字段判断是否有单文件失败

### 执行流程

```
start_sync
  ├─ 校验：源盘注册、磁盘水位（剩余 < 5GB + 下一文件大小则拒绝）
  ├─ 首次调用时清理孤儿暂存目录（>24h）
  ├─ 建暂存子目录 data/pan_sync_staging/<task_id>/
  └─ asyncio.create_task(_run_sync_safely)
       ├─ _collect_files：递归列出源盘文件清单（rel 路径 + size）
       ├─ 逐文件 asyncio.gather（Semaphore(2)）：
       │    ensure_dst_index(目标父目录)   ← 每层只列一次，删除/上传后失效重列
       │    同名+大小一致 → skipped++
       │    同名大小不一致 → dst.delete(先删) → uploaded++
       │    下载到暂存（百度侧解析「保存位置」后 move 到预期路径）
       │    dst.ensure_dir(父目录) → upload → 立即 unlink 本地副本
       │    单文件异常 → failed++ + 记 errors，不中断其他文件
       └─ finally：rmtree 暂存目录 + 释放 _running_keys
```

## 配置项

| 名称 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `PAN_SYNC_STAGING_DIR` | 环境变量（根 `.env`） | `<项目根>/data/pan_sync_staging` | 暂存根目录；空间紧张时指向更大的盘（如 `D:\pan_sync_staging`） |
| `PAN_SYNC_CONCURRENCY` | 环境变量 | `2` | 同时搬运的文件数 |
| `MIN_FREE_BYTES` | 代码常量 | `5GB` | 磁盘水位底线，改值需改 `pan_sync_service.py` |
| `ORPHAN_MAX_AGE_SECONDS` | 代码常量 | `24h` | 孤儿暂存目录清理阈值 |
| `MAX_FINISHED_TASKS` | 代码常量 | `100` | 内存保留的已完成任务数 |
| `MAX_RECORDED_ERRORS` | 代码常量 | `10` | 任务内记录的错误条数上限 |

依赖的既有配置：`PAN_ENABLED_PANS`（须含 baidu+quark 双向才可用）、`BAIDUPCS_BIN`、`KUAKE_BIN` / `KUAKE_WORKDIR`。

## 本地缓存目录与清理（三层）

1. **逐文件即删**：每个文件传完立刻删本地副本，磁盘峰值 ≈ 并发数 × 单文件大小（默认并发 2）；
2. **任务级 finally**：任务结束（含失败/异常）回收整个暂存子目录；
3. **孤儿兜底**：启动后首次同步时，清理暂存根目录下 mtime 超过 24h 的子目录（防 kill -9 / 断电残留）。

## 关键坑位（实测记录）

| 坑 | 说明 |
| --- | --- |
| BaiduPCS-Go 下载落盘路径 | 实际是 `savedir/用户ID_用户名/文件名`，不是 savedir 本身；从输出「保存位置:」行解析真实路径（`_DOWNLOAD_SAVED_RE`），不要自行拼接 |
| BaiduPCS-Go upload 遇同名文件 | 直接**跳过**（"目标文件已存在, 跳过"），不覆盖；覆盖必须先 `rm` 再传，同步服务已按此实现 |
| BaiduPCS-Go savedir 是全局配置 | `config set -savedir` 会写入登录态配置目录（macOS `~/.config/BaiduPCS-Go/pcs_config.json`，Windows `%APPDATA%\BaiduPCS-Go\`）；并发 2 下载时两个任务共享该配置，文件可能落进另一任务的暂存子目录——靠「保存位置」解析 + `shutil.move` 纠正，**不影响正确性** |
| 大小比对容差 | 同步查重不能用 `merge_pan_entries` 的 1024B 绝对下限（曾导致 24B 与 87B 误判为同一份而错误跳过）；`_sizes_match` 用纯 0.5% 相对容差（下限仅 1 字节），足够覆盖百度 ls 两位小数舍入（24.26MB 舍入误差约 5KB） |
| 百度 ls 最终一致性 | 上传后立刻 `ls` 可能读到旧大小/旧列表，同步可能「该跳过却覆盖」，无害（多传一次），下次即收敛 |
| kuake download 鉴权 | OSS 回调校验完整 Cookie；报「require login [auth expired]」是 **KUAKE_COOKIE 失效**，从浏览器 pan.quark.cn 重新复制整段 Cookie 更新 `kuake_cli/.env`（list/upload 不受影响，仅 download 需要） |
| Windows 下 CLI 输出编码 | 两个客户端封装都固定 `encoding="utf-8", errors="replace"`，Windows 服务运行时 stdout 不会是 cp936 乱码 |
| kuake stdin 陷阱 | kuake 对 delete/download 等命令在「stdin 非字符设备」时会进管道模式忽略路径参数；封装已固定 `stdin=subprocess.DEVNULL`，Windows 无控制台运行时也安全 |

## 排错

| 现象 | 原因与处理 |
| --- | --- |
| 同步失败：`require login [auth expired]` | 夸克 cookie 失效，重取 KUAKE_COOKIE（仅影响夸克→百度方向） |
| 「该路径正在同步中」 | 同一路径任务在跑；若任务实际已死（如服务崩溃），重启后端即释放 |
| 「本地磁盘空间不足」 | 暂存盘剩余 < 5GB + 下一文件大小；清理磁盘或改 `PAN_SYNC_STAGING_DIR` |
| 按钮不出现 | 对端盘未启用（`PAN_ENABLED_PANS`）、对端盘连接失败、或条目两边都有 |
| done 但 failed > 0 | 部分文件失败，看 `errors` 列表逐个处理（常见：单文件超时、目标盘空间不足） |

## Windows 环境部署

生产服务器（Windows）启用互传，在 doc 26 的百度接入基础上补以下配置：

### 1. `.env`（项目根）

```bash
# 夸克 CLI（kuake 源码内置默认路径，生产机对得上就不用配）
KUAKE_BIN=C:\Users\Administrator\Desktop\code\xianyu\kuake_cli\dist\kuake-windows-amd64.exe
KUAKE_WORKDIR=C:\Users\Administrator\Desktop\code\xianyu\kuake_cli

# 百度 CLI
BAIDUPCS_BIN=C:\tools\BaiduPCS-Go\BaiduPCS-Go.exe

# 双盘都启用（互传的前提）
PAN_ENABLED_PANS=quark,baidu

# 暂存目录：建议放空间大的盘（默认在项目根 data/ 下，C 盘空间紧张时必改）
PAN_SYNC_STAGING_DIR=D:\pan_sync_staging

# 可选：并发数（默认 2）
# PAN_SYNC_CONCURRENCY=2
```

### 2. 登录态（按 Windows 用户隔离，与 doc 26 一致）

- BaiduPCS-Go：cookie 登录态在 `%APPDATA%\BaiduPCS-Go\`。**用哪个 Windows 用户跑 backend-web，就用那个用户执行一次 cookie 登录**；以服务方式运行时尤其注意；
- kuake：cookie 在 `kuake_cli\.env` 的 `KUAKE_COOKIE`，整段复制自浏览器 pan.quark.cn；download 需要的完整 Cookie（含 `_UP_*`、`tfstk`、`__puus` 等）在 Windows 上同样适用。

### 3. 路径与编码注意

- 网盘远程路径一律 `/` 开头、与平台无关；本地路径由 Python `Path` 处理，Windows 反斜杠无需特殊处理；
- 服务代码中两个 CLI 封装的 stdout 都按 UTF-8 解析，Windows 下无控制台（服务方式）也能正常工作；
- 暂存目录所在盘需留足「最大单文件 × 并发数 + 5GB」水位。

### 4. 部署后验证

1. 网盘管理页顶部显示「已连接：夸克、百度」；
2. 找一个小文件，点「同步到X」，按钮转「同步中 1/1」，完成后 toast「同步完成：上传 1」；
3. 对端盘同路径出现文件即通；重复点一次应显示「跳过 1」（查重生效）。

## 日志与排查

**三层排查入口（由易到难）：**

1. **日志管理页「网盘同步日志」**（`/admin/pan-sync-logs`，管理员）：每次任务结束落一条 `xy_pan_sync_logs` 记录，
   含方向、路径、文件级统计（上传/跳过/失败）和错误明细（最多 10 条，页面展开查看）。
   支持按状态/网盘筛选、分页、清空。注意：`done` 状态也可能 `failed > 0`（部分文件失败），以文件统计为准。
2. **实时进度**：运行中任务不在日志页，看网盘管理页按钮上的「同步中 x/y」或接口 `GET /pan/sync-status/{task_id}`。
3. **日志文件**（深层排查）：`backend-web/logs/backend-web.log` 过滤 `[pan-sync]`；
   任务级异常堆栈同时在 `backend-web/logs/error.log`（仅 ERROR 级；日志默认保留 7 天，系统设置 `log.retention_days` 可调）。

落库实现：`pan_sync_service._persist_task_log` 在任务 finally 中尽力落库，落库失败只记警告、不影响任务。
接口：`GET /api/v1/admin/pan-sync-logs`（分页，参数 status/pan_type/page/page_size）、`DELETE /api/v1/admin/pan-sync-logs/clear`。
