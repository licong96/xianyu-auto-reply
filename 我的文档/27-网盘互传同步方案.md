# 网盘互传同步方案

- 状态：**已实施**（2026-10-21）
- 依赖：[23-多网盘并列查询与合并列表方案](./23-多网盘并列查询与合并列表方案.md)、[26-百度网盘接入部署与测试](./26-百度网盘接入部署与测试.md)

## 本文档解决什么

网盘管理页里，一个文件/文件夹只存在于百度或夸克其中一个盘时，点一下「同步到X」按钮，
自动把它搬到对端盘的**相同路径**，让一份文件同时出现在两个网盘、目录结构完全一致。
后续一键上架/发货可直接出两个盘的链接，不再需要人工「百度下载到本地 → 再上传夸克」。

## 使用方式

1. 网盘管理页，条目只在其中一个盘时，操作列出现「同步到夸克」或「同步到百度」；
2. 点击后按钮变「同步中 x/y」，后台逐文件搬运，完成自动刷新列表；
3. 两边都有的条目不显示按钮（所在网盘列显示两个盘即已同步）。

## 行为规则（已确认决策）

| 场景 | 行为 |
| --- | --- |
| 目标盘已有同名文件、大小一致（0.5% 容差） | 跳过，不重复上传 |
| 目标盘已有同名文件、大小不一致 | 视为旧版本，**先删目标再传**（直接覆盖） |
| 文件夹 | 递归同步整棵目录树，路径原样照搬 |
| 单文件 | 只搬该文件 |
| 中途失败 | 单文件失败记错误继续，其余文件不受影响；重跑靠查重补齐 |
| 服务重启 | 任务进度丢失（内存态），重新点一次即可，已传部分自动跳过 |

## 技术设计

### 代码位置

- `backend-web/app/services/pan/pan_sync_service.py`：同步服务（任务注册表、目录遍历、查重、覆盖、清理）
- `backend-web/app/services/pan/baidu_pan_client.py`：新增 `download / upload / ensure_dir / delete`（BaiduPCS-Go 封装）
- `backend-web/app/services/pan/quark_pan_client.py`：新增 `download`（kuake 封装）
- `backend-web/app/api/routes/pan_browser.py`：`POST /pan/sync`（启动任务）、`GET /pan/sync-status/{task_id}`（进度查询）
- `frontend/src/pages/pan-browser/PanBrowser.tsx`：同步按钮 + 2 秒轮询进度
- `backend-web/tests/test_pan_clients.py`：`TestBaiduSyncCommands` / `TestSyncSizeMatch` / `TestPanSyncService` 共 14 个新用例

### 流程

```
POST /pan/sync {pan_type, path, is_dir}
  -> start_sync：校验对端盘启用、防同路径重入、磁盘水位检查、建暂存目录
  -> 后台 asyncio 任务：
       1. 递归列出源盘文件清单（rel 路径 + 大小）
       2. 逐文件（并发 2）：
            目标盘同目录已有同名+大小一致 -> 跳过
            同名大小不一致 -> 先删目标盘旧文件
            下载到暂存目录 -> ensure_dir 目标父目录 -> 上传 -> 立即删本地副本
       3. finally：回收整个暂存目录
  -> 前端轮询 /sync-status/{task_id}，done/failed 后刷新列表
```

### 本地缓存清理（三层）

1. **逐文件即删**：每个文件传完立刻删本地副本，磁盘峰值 ≈ 并发数 × 单文件大小；
2. **任务级 finally**：任务结束（含失败/异常）回收整个暂存目录；
3. **孤儿兜底**：服务启动后首次同步时，清理暂存根目录下超过 24 小时未修改的目录（防 kill -9 残留）。

暂存根目录：`PAN_SYNC_STAGING_DIR`，默认 `<项目>/data/pan_sync_staging`。
磁盘水位：剩余空间 < 5GB 或不足以容纳下一个文件时拒绝/中止（`MIN_FREE_BYTES` 可调）。
并发数：`PAN_SYNC_CONCURRENCY`，默认 2。

### 关键坑位（实测记录）

| 坑 | 说明 |
| --- | --- |
| BaiduPCS-Go 下载落盘路径 | `savedir/用户ID_用户名/文件名`，不是 savedir 本身；从输出「保存位置:」行解析真实路径，不要自行拼接 |
| BaiduPCS-Go upload 遇同名文件 | 直接**跳过**（"目标文件已存在, 跳过"），不会覆盖；覆盖必须先 `rm` 再传，同步服务已按此实现 |
| BaiduPCS-Go 保存目录为全局配置 | `config set -savedir` 每次任务前设置，多任务并发会互相影响——当前并发仅限文件级（2 个文件同时传），保存目录在单文件下载内设置 |
| 大小比对容差 | 同步查重不能用 `merge_pan_entries` 的 1024B 绝对下限（曾导致 24B 与 87B 误判为同一份而错误跳过）；同步用纯 0.5% 相对容差，足够覆盖百度 ls 两位小数舍入 |
| 百度 ls 最终一致性 | 上传后立刻 `ls` 可能读到旧大小/旧列表，重复同步时偶发"该跳过却覆盖"，无害（多传一次），下次即收敛 |
| kuake download 鉴权 | OSS 回调校验完整 Cookie；报「require login [auth expired]」是 **KUAKE_COOKIE 失效**，从浏览器 pan.quark.cn 重新复制整段 Cookie 更新 `.env` 即可（list/upload 不受影响，仅 download 需要） |

## 排错

| 现象 | 原因与处理 |
| --- | --- |
| 同步失败：`require login [auth expired]` | 夸克 cookie 失效，重取 KUAKE_COOKIE（仅影响夸克→百度方向） |
| 「该路径正在同步中」 | 同一路径已有任务在跑，等完成或重启后端 |
| 「本地磁盘空间不足」 | 暂存盘剩余 < 5GB + 下一文件大小，清理磁盘或 `PAN_SYNC_STAGING_DIR` 指向更大盘 |
| 按钮不出现 | 对端盘未启用（PAN_ENABLED_PANS）或连接失败；条目两边都有时不显示 |
