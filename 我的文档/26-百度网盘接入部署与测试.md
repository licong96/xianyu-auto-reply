# 百度网盘接入部署与测试

- 状态：**已实施**（2026-10-16 补充部署与测试文档；客户端本身 2026-10-15 完成，见 [23-多网盘并列查询与合并列表方案](./23-多网盘并列查询与合并列表方案.md)）
- 依赖：[23-多网盘并列查询与合并列表方案](./23-多网盘并列查询与合并列表方案.md)、[08-夸克网盘桥](./08-夸克网盘桥.md)

## 本文档解决什么

百度网盘通过开源 CLI **BaiduPCS-Go**（`qjfoidnh/BaiduPCS-Go` 分支，v4.0.2 实测）接入，与夸克并列。换一台新电脑（或新服务器）部署时，按本文档步骤操作即可把百度盘跑起来；文末是排错与单元测试说明。

核心语义先记住一句：**文件可以只存在于一个网盘**。某个文件夹只在夸克有时，百度查不到该路径是正常情况，页面不报错、不标红（`PanPathNotFoundError` 按「该层为空」处理）；只有登录失效、CLI 挂掉这类真实故障才标失败。

## 一、新电脑部署步骤

### 1. 下载 BaiduPCS-Go

 release 页：<https://github.com/qjfoidnh/BaiduPCS-Go/releases>

| 平台 | 下载包示例 |
| --- | --- |
| Windows 服务器 | `BaiduPCS-Go-v4.0.2-windows-amd64.zip` |
| macOS（本机 Apple Silicon） | `BaiduPCS-Go-v4.0.2-darwin-arm64.zip` |
| Linux amd64 | `BaiduPCS-Go-v4.0.2-linux-amd64.zip` |

解压后把二进制放在固定目录（建议项目外的工具目录，如 `~/tools/` 或 `C:\tools\`），后续 `.env` 里填这个绝对路径。

### 2. 登录（cookie 方式，最稳）

BaiduPCS-Go 登录需要百度账号的 `BDUSS` 和 `STOKEN` 两个 cookie：

1. 浏览器登录 <https://pan.baidu.com>；
2. 开发者工具（F12）→ Application/应用 → Cookies → `https://pan.baidu.com`，复制 `BDUSS` 和 `STOKEN` 的值；
3. 命令行执行（cookie 值用引号包住）：

```bash
BaiduPCS-Go login -cookies="BDUSS=这里填; STOKEN=这里填"
```

登录成功后提示用户名即完成。**登录态持久化在用户配置目录**，之后后端每次 subprocess 调用都免登录：

- macOS / Linux：`~/.config/BaiduPCS-Go/`（本机实测，含 `pcs_config.json`）
- Windows：`%APPDATA%\BaiduPCS-Go\`

> 换电脑 = 重新做一次 cookie 登录。cookie 失效的表现是状态检查报「请尝试重新登录」，按上面步骤重来即可。

### 3. 配置 `.env`

```bash
# BaiduPCS-Go 二进制绝对路径（按实际解压位置填）
BAIDUPCS_BIN=/Users/xxx/tools/BaiduPCS-Go
# Windows 示例：BAIDUPCS_BIN=C:\tools\BaiduPCS-Go\BaiduPCS-Go.exe

# 启用的网盘（逗号分隔）；只配了夸克就保持 quark，不配百度相关项不生效
PAN_ENABLED_PANS=quark,baidu

# 网盘管理页的根目录（默认 /闲鱼）：页面默认进入该目录，
# 地址栏里的 "/" 是它的别名，越出该目录的路径自动收拢回来；资料池里的绝对路径不受影响
# PAN_ROOT_DIR=/闲鱼
```

### 4. 重启后端并验证

重启 backend-web 后打开「网盘管理」页：

1. 顶部应显示「已连接：夸克、百度」（无红色报错横幅）；
2. 只在夸克存在的文件夹照常列出，不提示百度失败；
3. 点「分享」，夸克、百度各出一条链接和提取码。

接口层验证（已登录会话）：

```bash
curl -H "Authorization: Bearer <token>" "http://localhost:8100/api/v1/pan/status"
curl -H "Authorization: Bearer <token>" "http://localhost:8100/api/v1/pan/entries?path=/资料池"
```

`/pan/entries` 返回里，路径不存在的盘是 `{"pan_type": "baidu", "ok": true, "missing": true}`；真实失败才是 `{"ok": false, "error": "..."}`。

## 二、技术要点（改代码前读）

代码位置：`backend-web/app/services/pan/baidu_pan_client.py`（协议定义与注册表在同目录 `base.py`）。

| 要点 | 说明 |
| --- | --- |
| 无 JSON 输出 | BaiduPCS-Go 的 `ls`/`share list` 是人类可读表格，按固定列解析（行首序号、大小、日期、名称；目录名以 `/` 结尾；剔除 `----` 分隔线与汇总行）。改解析逻辑后跑单测防回归 |
| 错误码 `-9` = 文件不存在 | `ls` 一个不存在的路径返回 `代码: -9, 消息: 文件不存在`。客户端抛 `PanPathNotFoundError`（继承 `PanError`），路由层按「该层为空」处理。匹配用正则 `代码:\s*-9\b`，`-90`/`-19` 等相似码不会误判 |
| 夸克侧等价物 | kuake_cli 返回结构化 `code: "FILE_NOT_FOUND"`，同样映射为 `PanPathNotFoundError` |
| `ls` 不输出 fs_id | 百度查重按**路径**反查（`share list` 的「特征路径」列），不依赖 fid；`find_share` 以 path 为准 |
| 大小精度 | 百度 `ls` 大小是 2 位小数人类可读（如 `24.26MB`），合并比较带 0.5% 容差，避免同一文件被误标「大小不一致」 |
| 分享有效期 | `share set --period 天数`（0=永久），默认取 `KUAKE_SHARE_DAYS`（与夸克对齐，默认 30 天） |
| 失败分级 | 路由 `/pan/entries` 中：路径不存在 → `ok: true, missing: true`；真实失败 → `ok: false, error`；全部失败才整体返回错误。分享一个不存在的路径仍会失败并在分享弹窗标红（确实分享不出去） |
| 网盘根目录 | `PAN_ROOT_DIR`（默认 `/闲鱼`）是网盘管理页的根：不传 path、传 `/` 或越出根目录的请求都收拢到它（`..` 也不越出），响应带 `root` 供前端做面包屑起点。资料池匹配用的绝对路径不受影响 |

## 三、排错

| 现象 | 原因与处理 |
| --- | --- |
| 顶部横幅「百度网盘连接失败：…请尝试重新登录」 | cookie 失效，重做一次 §一.2 的登录 |
| 顶部横幅「…BaiduPCS-Go 二进制不存在」 | `.env` 的 `BAIDUPCS_BIN` 路径不对，或解压后没给执行权限（`chmod +x`） |
| 分享时报「-9 文件不存在」 | 该路径在百度盘上确实不存在（只在夸克有）。分享弹窗里只勾选实际存在的盘；这是预期行为不是故障 |
| 上传/转存空间不足 | 百度账号容量见底时分享正常但存不进新文件。曾遇到 12TB 用 99.94% 的账号，正式用前需清理 |
| Windows 服务方式运行时登录态丢失 | 登录态按用户隔离。用哪个 Windows 用户跑后端，就用那个用户做一次登录 |

## 四、单元测试

测试文件：`backend-web/tests/test_pan_clients.py`（17 个用例），覆盖：

- 夸克/百度客户端对「路径不存在」的识别与其他错误的区分（含线上真实报错文本样本、`-90`/`-19` 防误判）；
- `ls` 输出解析（夸克 JSON、百度表格两种形态）；
- `merge_pan_entries` 合并规则（同名合并、单侧存在、大小写不敏感）；
- `/pan/entries` 路由的失败分级（missing 不标失败、真实失败标红、全失败返回错误）。

运行：

```bash
cd backend-web
.venv/bin/python -m pytest tests
# Windows: .venv\Scripts\python -m pytest tests
```

改网盘相关代码后跑一遍，绿了就说明「路径不存在 ≠ 错误」的语义没有被破坏。
